## Usage

```tsx
import { Dropzone } from "@/components/dithercn/dropzone";

export function Attachments() {
  return (
    <Dropzone
      accept="image/*,application/pdf"
      maxSize={10 * 1024 * 1024}
      maxFiles={5}
      onFilesChange={({ accepted }) => upload(accepted)}
    />
  );
}
```

Drag files over the zone, click it, or focus it and press Enter or Space to open the file picker. Each drop or pick is checked against `accept`, `maxSize` and `maxFiles`, and `onFilesChange` gets both lists: the accepted `File` objects, and the rejected ones with a `reason` (`"file-type"`, `"file-too-large"` or `"too-many-files"`) and a short `message`. The zone keeps no list of its own, so you decide what to keep, upload or show.

The border is a row of dithered dashes, each a solid head with a tail that thins through the Bayer levels, marching slowly clockwise round the edge. With files over the zone the dashes lengthen and speed up, a second ring of cells fills in, and a glow is pulled in from the edges, its front moving inward. The sheet in the illustration drops into the tray in whole-cell steps. While a drag is over it, the zone can see how many files it carries and their types, so a drag it would refuse turns red, stops marching and shakes the sheet. Sizes are only known on drop, so a file that is too large turns the zone red after the drop and names the file. A rejection stays until the next drag or pick, so a long filename can be read in full.

Without a `description`, the line under the title is written from the rules, such as "Images or PDF, up to 10 MB each, 5 files at most". Hover and keyboard focus light the border a little, so the zone reads as something you can act on.

### File list

`DropzoneFileList` shows files with a [progress bar](/docs/charts/progress-bar) each: the zone's colour while uploading, solid green when done, hatched red with the message when it failed. Leave `progress` as `null` for an upload whose size you can't measure, and the bar becomes indeterminate.

```tsx
import { DropzoneFileList } from "@/components/dithercn/dropzone";

<DropzoneFileList
  files={[
    { id: "1", name: "brand-guide.pdf", size: 3_870_000, status: "done" },
    {
      id: "2",
      name: "reel.mp4",
      size: 41_200_000,
      status: "uploading",
      progress: 38,
    },
  ]}
  onRemove={(id) => remove(id)}
/>;
```

`DropzoneFileList` takes `files` (each `{ id, name, size }` plus `status: "uploading"` with `progress` from 0 to 100 or `null`, `status: "done"`, or `status: "error"` with a `message`), `onRemove`, `color` and `fill`.

## Notes

- The zone is one control, a native `<button>` in the tab order, named by its title and the browse label and described by the hint. Enter and Space open the picker. The real `<input type="file">` sits next to it, hidden from view and from assistive technology, and is emptied after every pick so choosing the same file again still counts. With `name`, a second hidden input holds the accepted files from the last drop or pick for the form.
- A polite live region announces every result, such as "Added 3 files: a.png, b.png, c.pdf." or "Did not add report.exe: only images or PDF."
- The border is a canvas drawn one pixel per cell and scaled up without smoothing, with no WebGL. It pauses offscreen and in hidden tabs. With reduced motion the dashes hold still, the drag-over and reject looks switch in one step, and the illustration stops bobbing and shaking. Before the first frame it shows a plain dashed edge.
- The file list is a list of progress bars, each with `role="progressbar"`, and every remove button is labelled with the file's name.
